# F-DAT-12 evedb, the Eve test database

A database server in Zig around DuckDB, outside the VM, that speaks the database frames of EWP; the remote database of the level 5 tests, with fault injection and a statement log (`drivers/duckdb/README.md`).

*Partial (2026-10-18):* detailed design in `drivers/duckdb/README.md`; version 0.3: column batches on the native protocol (`QUERYB`, `LOAD` into DuckDB's Appender), the driver `evedb://` with `Memory.store` and `Memory.load`, measured by `script/evedb_bench.py` (1,000,000 rows into a `Memory` table in 0.23 s; a group-by 55 times faster than SQLite),; triggers and stored procedures in evedb dropped. Version 0.2: evedb answers the **PostgreSQL protocol** on port 5432 (logins trust, password, md5; simple and extended query; types, errors, transactions), a configuration file, `eve db serve` and `eve -s -db --serve`; tested by `script/pg_check.py` (psycopg2, pg8000) and; stored procedures and triggers in Eve designed (version 0.3). Version 0.1 built: the server of the EWP-db frames, sessions with leases, `eve_tx` and `STATUS`, error classes, seven faults, the statement log, tokens, and the commands `serve`, `create`, `sql`, `describe`, `snapshot`, `reset`, `status`, `stop`; 16 unit tests and 66 protocol checks in Python (`script/evedb_check.py`). Not yet: the Eve driver `evedb://`, change sets (`CHANGES`/`APPLIED`), `BATCH`/`CREDIT`, the appender, `drift`, import and export, service mode (0.2).

*Moved to level 7 (2026-10-20):* evedb is the server; levels 1 to 6 are the client. The column batches of are kept with their tests.
