# 07 The Zig virtual machine (`RVM`)

Read: `evevm/README.md`, `src/` layout (≈5 600 lines: `interp.zig` 2 091, `parser.zig` 1 226, `vm.zig` 662, `cli.zig` 578), the header and data types of `interp.zig`, `lib/`.

## Advantages

**RVM-A01 Zig is a good host.** No runtime, cross-compilation to every OS and to `wasm32` from one build, explicit allocators, C ABI for database client libraries. It is the right language for a VM that must later run in a browser and on a server.

**RVM-A02 Small, readable pipeline.** Lexer → parser → AST → tree walker, each in its own file, plus a command slot / serve mode (`vm.zig`, `cli.zig`, D-063) that already lets scripts drive the VM through a session. The serve mode is a seed of the future server process.

**RVM-A03 Arena allocation per run.** "Every value the script creates is allocated from one arena and freed together when the run ends" (`interp.zig` header). Simple, fast, no leaks for batch scripts — and the right idea at the wrong granularity (`RVM-R02`).

**RVM-A04 Library written in Eve with `external` primitives.** D-053, D-056. Keeps the native surface small, which is what a WASM port and a second implementation need.

## Disadvantages

**RVM-D01 Tree walker on the Zig call stack.** Control flow is carried by Zig errors (`Signal`: `Raise, Break, Next, Over, Panic, Retry, Resume, Abort, Stop`), and every Eve call is a Zig call. Consequences already recorded in `design-multitasking.md` §5: no generator can be suspended in a nested loop, no task can be moved to another worker, no stack can be saved while waiting on I/O. All three are required by D-067 (generators, "a waiting aspect gives its core away").

**RVM-D02 Names are resolved at run time by string comparison.** `Scope.find` walks the parent chain and compares names with `std.mem.eql` on every variable access. Fine for tests, 10–50× slower than slot indexes, and it hides undefined-name errors until the line runs (the "gradual type system" can't report them early).

**RVM-D03 One arena for the whole run.** A long-running process (server, a nightly ETL over 10 GB) never frees anything until it exits. Memory grows with every row processed.

**RVM-D04 Collections are linear.** `Map` is an `ArrayList(Entry)` searched by `mapFind`; DataSets are sorted lists. Lookup is O(n), insertion O(n). An ETL join on 100 000 keys becomes quadratic.

**RVM-D05 Interpreter-global state for expression context.** `Interp.dollar` holds "the last index of the dimension being indexed". Nested indexing (`a[b[$]]`, `m[$][v[$]]`) depends on save/restore discipline; this kind of global is what breaks first when evaluation becomes concurrent.

**RVM-D06 Error codes are `u8`.** `Report.code: u8`, `Outcome.code: u8`. The integer error model (`RST-D04`) is wired into the VM types.

**RVM-D07 Stale README.** `evevm/README.md` says "skeleton … running a script is not implemented yet"; the interpreter runs all of level 1.

## Antipatterns

**RVM-X01 Using the host language's exceptions for the guest language's control flow.** Error unions as `break`/`next` signals is elegant for a teaching walker, but it fuses the Eve stack to the Zig stack, which is precisely what must be separated for generators, scheduling and WASM (no stack switching in WASM MVP).

**RVM-X02 Didactic comments at a ratio that competes with code.** 115 `Zig tip` blocks in `interp.zig` alone, many of them "relies on the same Zig feature as `List` above: see the tip there". The rule in CLAUDE.md forces a tip on every declaration; the useful tips get lost among the references. Teaching material belongs in `evevm/doc/zig-tour.md` with links from the code.

## Recommendations

**RVM-R01 Bytecode VM now, before generators and parallelism.** Compile the AST to a compact register- or stack-based bytecode with an explicit frame stack in the heap. A frame is then a value: a generator is a saved frame, a waiting aspect is a parked frame list, a remote call can serialize arguments and resume a frame on reply. The tree walker can stay as the "student reference" implementation (`--engine=walk`), and the conformance suite proves both equal.

**RVM-R02 Region memory that follows the language.** One arena per aspect call (state dies at `return`, D-066), one per job (reset on `retry`), one per request on the server; module singletons and channel buffers in a long-lived heap with reference counting; values crossing a boundary (`@` outputs, channel `send`) are copied — which the language already requires. This gives deterministic memory without a tracing GC, and a hard memory limit per request.

**RVM-R03 Resolve names at compile time.** A resolver pass assigns slot indexes and reports undefined names, wrong arity and visibility errors before the run (exit code 65 "check-time" is already mentioned in Q-022 b).

**RVM-R04 Real data structures.** Hash index + sorted order for `Map` (or a B-tree), a hash set + sort-on-iterate for DataSet, ropes or chunked buffers for `Text`, columnar buffers for `Table` (`RTY-R06`).

**RVM-R05 A portable, versioned bytecode file (`.evb`).** Header with spec version, required capabilities, constant pool, functions, debug line table, hash. It is what the server deploys, what the browser downloads, what a cache stores. The source stays the source of truth; `.evb` is the unit of distribution.

**RVM-R06 Build the VM for `wasm32-wasi` and `wasm32-freestanding` in CI from day one.** Zig makes it one target flag. Every native feature then has to declare a host import, which keeps the `external` surface honest (`RNW-R06`).

**RVM-R07 Embedding API.** `evevm` as a library with a C ABI (`eve_vm_new`, `eve_load`, `eve_apply`, `eve_free`) so the server, a browser host, and test tools all drive the same core. `cli.zig` becomes one client of it.
