## Highlights

- **A full-screen prompt** (`F-TLS-02` REPL, drafted): `eve` at a terminal shows a banner, an upper part for the output with its own scrollback (Page Up and Down, the arrows), the command line between two rules, and a status bar that says `Ready`, `Running…` (blinking) while a command runs, and the time of the last run. The window can be resized.
- **A real `help`** (`F-TLS-02`): a table of the commands with a line between them, 100 characters wide (`EVE_WIDTH` or `eve_width` in `eve.cfg` change it, a narrower window wins), and `help <command>` (also `? <command>`, `<command> ?`) with the syntax, the options and examples. The tables and the texts are drawn again when the window changes size.
- **The machine at the prompt** (`F-NET-02` HTTP server, `F-NET-08` the machine API, both drafted): `listen` and `serve` open the IPC and HTTP doors inside the prompt, `status` shows the configuration, the ports and what the machine is doing (`vm.stat` reports the requests, the uptime and the running script), and `stop` closes both doors and tells the running scripts to stop without leaving the prompt.
- **Commands without the prompt:** `eve <command>` runs once and ends (`eve check a.eve`, `eve stop`); `evevm` starts the machine in a new process and returns to the system prompt (`evevm stop|restart|status`); `eve -u` opens the user interface, the web page of the machine, when it is not open.
- **The language and its tests:** levels 1 to 5 and the smoke test pass, 349 of 349 (see Progress): the data language, `sql function` and Eve stored procedures (`F-DAT-13`, `F-DAT-14`, drafted), the machine API tests (`e95`).

## Decisions

This is the first release, so the notes do not compare with an earlier one. The decisions that shape what is delivered (`python script/plan.py show D-nnn` prints one):

- `D-153` Release policy: release notes in `manual/release/`, the manual updated at every release.
- `D-154` eveux, the RAD Workbench, is written in Eve: the final test of the language (design only here).
- `D-155` One local machine, many remote machines: a login per machine, single sign-on, the keyring.
- `D-156`, `D-158`, `D-159` The core database: one per project, the answers of the author to the database layer, remote databases.
- `D-160` Eve is project oriented: `project new <folder>` and the project folders.
- `D-161` `then` is removed from `match` and the loops.
- `D-162` The machine: doors, `-loc`, `-rem`, `--serve`.
- `D-163` to `D-165` Modules and one binary (`eve vm`, `cp`, `db`, `ux`); the serving machine; the machine API `vm.*`, `db.*`.
- `D-166` Stored procedures, `sql function`, SQLite embedded and DuckDB on demand.
- `D-167` One version; version N is level N.
- `D-168` The answers of 2026-10-13: `$err_sql`, `null` prints `null`, `time.now!()`, Decimal and Real conversions.
- `D-169` `--listen [word]` replaces `-lsn [port]`: the two doors take the same words.

The screen, `help`, `stop`, `evevm` and `-u` of this release were asked for by the author in conversation and have no decision number yet.

## Breaking changes and migration

None for existing scripts. For people who typed commands:

- `-lsn [port]` is gone (D-169): use `--listen`; the old option is now an unknown option (exit status 64).
- At the prompt, `clear` now clears the upper part of the screen. It was a stub that printed "not yet implemented", so no script depended on it; the `clear` command of a slot file (`-i`) still forgets the current script.
- At the prompt, `stop` now closes the doors and stops the scripts of the machine; it was a stub. In a slot file it is unchanged.
- The `status` command prints the state of the machine; it still adds one line for the script to `summary.log` (but writes nothing when no script is loaded).
- `eve <word>` where the first word names a command now runs that command (`eve status`, `eve stop`). A word that ends in `.eve` still runs as a script.

## Known issues

- **`-u` has two meanings in the plan.** `D-083` (and the row `F-TLS-13`) gives `eve -u <file>` the meaning "upload a source file to a machine"; this release makes `-u` open the user interface, as the author asked. The upload needs another letter. Open: a decision of the author.
- **Not tried:** the opening of the browser by `eve -u` was not run (the case "the interface is already open" was), and the code for Linux and macOS (window size, starting `evevm` without a window, `xdg-open`) was written but not compiled or run there. The screen was tested on Windows in a pseudo-terminal (ConPTY).
- **The user interface has no page yet.** `-u` opens the web folder of the project; the workbench `eveux` is design only (`D-154`, `Q-047`). The command prints a note when `web/index.html` does not exist.
- **Not implemented at the prompt:** `compile`, `debug`, `begin`, `enter`, `print`, `resume`, `setup` still print "not yet implemented" (`help` says so for each).
- **Plain output is cut, not wrapped, below the width of the window:** a line of a script longer than the window is cut on the screen (the scrollback keeps it); lines over 120 characters are split. The help tables and texts do wrap.
- **The log of a machine started by `evevm`** is a file in the runtime folder; the request log is not shown anywhere else.
- The stage of `F-TLS-02`, `F-NET-02` and `F-NET-08` stays *drafted* (partial): the rows of `plan/version_map.md` say what is missing.
- All 349 tests pass; no test fails.

## Performance

<!-- GEN:performance (script/relnotes.py) -->
Total median time of the benchmarks of each level, ReleaseSafe build, run of 2026-10-13 11:44 (commit `505c7dc`), against the twins in Python and against version 0.0.2 (2026-10-09). Notes by version and history: [test/bmark/README.md](../../test/bmark/README.md).

| Benchmarks | Eve | Python | Eve / Python | Change |
|---|---|---|---|---|
| Level 1 | 308 ms | 165 ms | 1.9x | -6% (faster) |
| Level 2 | 118 ms | 101 ms | 1.2x | +4% |
| Level 3 | 228 ms | 117 ms | 1.9x | +0% |
| Level 4 | 751 ms | 618 ms | 1.2x | -19% (faster) |
| Level 5 | 91 ms | 112 ms | 0.8x | - |
<!-- /GEN:performance -->

The work of this version is around the interpreter, not in it. The only change on the path of a running script is that the poll between two statements also reads one shared counter (so that `stop` can end a script); `p1a_arith` moved +2%. Levels 1 and 4 are faster than the last saved run (-6% and -19%) and I did not find a cause, so I read it as noise of the machine. One benchmark dropped more than 10%: `p3b_objects` +17% (median 89.2 ms, best 79.4 ms); nothing in this version touches objects and the spread of that benchmark is as large as the change, so it is attributed to noise but not proven. `p5a_sql_function` is new (91 ms, 0.8x its Python twin). The size of `eve.exe` is recorded for the first time (3,572 KB, ReleaseSafe).
